# 城市霞况准确率与有界概率校准

`forecast` 只读取 `accuracyStats` 中按城市聚合的近 30 天统计，用于对模型估算的**出现概率**作小幅校正。它不会读取个人反馈、身份、精确位置或单条观测。

## 聚合统计格式

每条 `accuracyStats` 记录按机器城市代码和场景保存：

```json
{
  "cityCode": "101020100",
  "sceneType": "sunset",
  "windowDays": 30,
  "status": "ready",
  "sampleCount": 36,
  "hitCount": 29,
  "accuracyRate": 0.8056,
  "coverageStart": 1785320400000,
  "coverageEnd": 1787912400000
}
```

- `cityCode` 是唯一的城市查询键；不使用中文展示名。
- `sceneType` 只能是 `sunrise`、`sunset` 或 `fireCloud`。
- 记录必须覆盖完整、最新的 30 天窗口，且有至少 30 条有效样本，才可参与校准。
- `accuracyRate` 必须与 `hitCount / sampleCount` 一致（仅容许 0.0001 的比例舍入误差）；它仅用于兼容性校验，校准实际使用由计数重新计算的比率。不一致的聚合记录会被安全忽略。
- 查询、字段校验或数据库超时失败时，预报保持原始概率并继续返回。

## 四档命中规则

预报评分和实际观测都映射到 0–3 四档：

| 预报评分 | 预报档位 |
| --- | --- |
| 0–39 | 0 |
| 40–59 | 1 |
| 60–79 | 2 |
| 80–100 | 3 |

实际观测使用 0–3 档。预报档位与实际档位相差不超过 1 档时记为命中；`accuracyRate = hitCount / sampleCount`。旧版 `observedScore` 仅在聚合时兼容转换，不会传入预报校准逻辑。

## 有界校准规则

- 样本少于 30 条、统计异常或统计不新鲜时，概率原值返回，显示为数据积累中。
- 统计有效时，只按对应场景的城市准确率微调出现概率，最大幅度为 **±5 个百分点**。
- 校准不会改变霞况评分、火烧云鲜艳度、可信度或天气数据。
- `accuracyRate` 是历史命中表现，**不是**本次霞况的出现概率；页面标签必须保留这一差异。

因此，城市统计只能让模型估算略微偏向或保守，不能替代本次基于天气和模型特征计算的出现概率。

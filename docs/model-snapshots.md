# 多模式云量参考数据

`modelSnapshots` 用于保存已经同步的 EC / GFS 数值与云量图，供后台历史管理和后续图像任务使用。当前小程序详情页不再展示多模式云系参考卡片，首页评分也不读取此集合。

## 创建集合

在云开发数据库创建集合 `modelSnapshots`，权限设置为“仅管理员可读写”。客户端不会直接读取该集合；实时评分由 `forecast` 云函数按用户 GPS 即时请求 EC/GFS。

## 单条记录格式

```json
{
  "source": "EC",
  "status": "ready",
  "city": "全国",
  "runAt": 1780000000000,
  "validAt": 1780021600000,
  "imageFileId": "cloud://环境ID.云存储路径/ec/20260728-1200.png",
  "totalCloud": 56,
  "lowCloud": 20,
  "midCloud": 35,
  "highCloud": 42,
  "precipitation": 0,
  "humidity": 68,
  "visibility": 18,
  "note": "全国总云量参考图"
}
```

- `source`：仅使用 `EC` 或 `GFS`。
- `status`：只有 `ready` 才会对用户可见。
- `city`：全国图填 `全国`；未来也可为单个城市存储局地裁切图。
- `runAt`：模式起报时间；`validAt`：该图有效时间，均为 Unix 毫秒时间戳。
- `imageFileId`：云存储中的图片文件 ID；也可使用 `imageUrl` 存放受控图片地址。
- `totalCloud`：目标时段的总云量，范围为 0–100；`precipitation`：目标时段预报降水量，单位为毫米。这两个字段同时存在时，详情页才会计算 EC / GFS 的模式一致性。
- `lowCloud`、`midCloud`、`highCloud`：低、中、高层云量，范围均为 0–100；`humidity`：相对湿度，范围为 0–100；`visibility`：能见度，单位为公里。以上字段为可选字段，可在 1.0.9 的“模型数值解读”中补充解释。

云函数会选择与观赏时段最接近、且时间差不超过 6 小时的记录。缺少有效时段或数值信号时，详情页会显示“数据不足”；已同步数值、但尚未上传云量图时，会显示“图卡待同步”。

## 一致性规则

仅比较同一城市（或全国图）且最接近目标观赏时段的 EC、GFS 记录：

- 云量差不超过 15%，且降水信号一致：`较一致`；
- 云量差不超过 30%，且降水信号或云量分档相近：`存在差异`；
- 其他情况：`分歧较大`；
- 任一模式缺少 `totalCloud` 或 `precipitation`：`数据不足`。

2.0 版本开始，首页 `forecast` 会根据本次请求携带的用户经纬度即时请求 EC/GFS 原始特征，并与本地逐小时天气特征融合参与霞况评分；不再通过 `modelSnapshots` 查询评分数据。当前详情页也不展示多模式云系卡片，集合仅保留给后台历史管理与后续图像任务。EC/GFS 模式差异会影响可信度与安全上限；历史概率校准由 `skyObservations` 集合提供，样本不足时仍显示“模型估算概率（待校准）”。

## 归属

EC 图卡需要保留 ECMWF 数据来源标注；GFS 图卡需要保留 NOAA/NCEP 数据来源标注。请只上传基于可合法使用的原始数值预报自行渲染的图像，不抓取第三方应用截图。
